# Blueee Notes

在多台设备之间同步所选的 Obsidian 笔记、附件与社区插件清单。新用户需要 Blueee Notes 账号和管理员发放的注册口令。账号只用于连接同步仓库，注册免费。

## 注册与跨设备使用

在要同步的 Obsidian 仓库启用 Blueee Notes，打开插件设置并选择「用口令注册并创建首个仓库」。输入账号、至少 12 个字符的密码、管理员发的口令，以及远端仓库名（默认 main）。你的另一台设备选择「登录并连接已有仓库」，使用同一个账号、密码和远端仓库名。其他本地仓库可以连接不同的远端仓库，同一账号可在新本地仓库里用「已有账号，新建远端仓库」创建另一个。各账号的仓库彼此独立。

## 同步社区插件清单

在设置中点「插件同步 → 打开插件清单」，在来源设备上传本机清单，在另一台设备查看远端清单。清单含插件名称、ID、版本和启用状态，以加密形式存放在同一个远端仓库。点击条目可打开 Obsidian 社区插件页面，再由用户安装或更新。插件程序、插件设置及各设备的登录凭据保留在本地。每次上传替换该仓库的远端清单。

## 隐私和网络服务

Blueee Notes 通过 HTTPS 连接运营者的同步服务 `https://blueee.cn:8443/simple-sync`，用于注册、登录和同步。服务端保存账号名、密码证明的散列、会话令牌的散列、仓库名和加密数据；同步内容和清单在设备上加密，仓库密钥用密码派生的独立密钥包裹。注册口令仅在注册时经 HTTPS 发送以供校验，管理员设置的口令以散列保存。原始账号密码保留在本次登录表单和客户端计算中，服务器收到的是独立派生的登录证明。请妥善保管密码，当前版本没有邮件重置或密码找回功能。账号会话到期后可重新登录。

## 笔记同步

点击刷新图标打开同步面板。开启「自动同步」后，插件会在打开笔记和暂停输入后同步当前 Markdown 笔记，Obsidian 在前台时还会定期检查远端改动。已有仓库首次升级时需要主动开启这个开关。

需要手动操作时，选择「仅拉取」「双向同步」或「仅推送」，再选当前笔记、一个文件夹或当前仓库。「按上次范围同步」会复用上次的手动范围和方向。文件夹包含子文件夹。单篇模式仅同步所选文件，引用的附件可通过文件夹或整个仓库一起同步。

## 开发安装与旧版配对

运行 `npm ci` 和 `npm run build`。在测试仓的插件目录新建 `simple-note-sync`，复制 `dist/main.js`、`dist/manifest.json` 和 `dist/styles.css`，重启 Obsidian 后启用「Blueee Notes」。Windows、Android 和 iPadOS 通过同一套 Obsidian API 工作，手机端需单独验证插件安装和使用。

已有测试仓可在设置中继续使用旧版配对 JSON。它由 `url`（如 `https://blueee.cn:8443/simple-sync`）、`token`（仓库授权）和 `key`（Base64 编码的 32 字节仓库加密密钥）组成。每个新仓库生成一个随机密钥并妥善保管。同一个仓库的设备使用同一个密钥。配对 JSON 包含凭据，存放在仓库之外，私下交付。

## 管理

在 Windows 双击 `打开同步管理.cmd`，选择「设置注册口令」并输入至少 12 个字符。只有拿到口令的人可以注册，换口令或关闭注册后已有账号仍可登录。管理员可以在同一窗口查看、停用和重新启用账号。停用会撤销已签发的登录会话。注册账号与旧版配对记录分开管理。


Windows 上双击 `打开同步管理.cmd`，使用已配置的 `ssh blueee-server` 连接。可以新建用户和仓库、发放配对配置、重置凭据、撤销授权。管理员通过 SSH 操作，用户的配对配置只能访问授权仓库。

新建仓库的密钥生成并保存在管理员电脑的 `%LOCALAPPDATA%\SimpleNoteSyncAdmin\vault-keys.json`。已有仓库可选中后从对应的配对 JSON 导入密钥。请单独备份仓库密钥。

在服务器通过 SSH 运行以下命令。用户名和仓库名区分大小写。

```sh
runuser -u simple-note-sync -- python3 /srv/simple-note-sync/server.py --db /srv/simple-note-sync/data/sync.sqlite3 grant alice reading
runuser -u simple-note-sync -- python3 /srv/simple-note-sync/server.py --db /srv/simple-note-sync/data/sync.sqlite3 list
runuser -u simple-note-sync -- python3 /srv/simple-note-sync/server.py --db /srv/simple-note-sync/data/sync.sqlite3 revoke alice reading
```

`grant` 创建账号和仓库（若不存在），为指定组合发放令牌。再次发放会使原令牌失效。要做共享仓库，给需要访问的人员分别授权同一个仓库，并由仓库拥有者分发该仓库的加密密钥。停用账号的某项授权不会删除仓库文件。重新授权需要用户重新导入配对配置。

## 同步行为

- 服务器保存加密的路径、内容摘要和文件。每次会获取加密目录，用于在设备本地确定范围。只有选中范围的文件内容会上传或下载。
- 双向同步时，有共同旧版本且改动不重叠的小型 Markdown 会尝试自动合并。遇到冲突，插件将远端版本另存到 `Sync conflicts`，保留当前文件，并暂停该篇的自动同步。同步面板的「处理冲突」可以对照本机、共同旧版本和远端内容，再选保留本机、采用远端或手动保存合并结果。
- 仅推送时，遇到冲突会跳过该文件。仅拉取时，可在本地查看冲突副本，远端文件不会被改动。
- 已同步文件的删除会作为变更参与同步。另一端只有在原文件没有本地修改时才移到回收站。
- 服务器始终保留每篇文件的最新加密版本。设备按文件确认已同步的修订。旧版本至少保留七天，只有最近三十天内确认过这个文件的设备都已越过该修订，服务器才会在后续确认时清理它。没有共同旧版本时，冲突留给用户处理。
- 当前原型单文件上限为 32 MiB。先在独立测试仓使用，确认移动端行为后再迁移正式笔记。

运行 `npm test` 可用临时 SQLite 和本机 HTTP 服务执行端到端测试。
